# 11 面板里拖动排序与拖出删除

先读 [00 总览](00-overview.md) 与 01–10 十份文档，并以 10 阶段合入后的代码为基线。本阶段交付需求 26、27：面板里把文件夹的一项拖出面板，即从文件夹里删除这一项，剩下的项按原来的顺序补上空位；在面板里拖动文件夹的项，调整它们在文件夹里的顺序。

## 规则

### 范围

- 只在文件夹的层级：根层级与子层级
  - 每一种项都能拖：App、子文件夹、文件、访达里的文件夹、网页
- 访达里的文件夹的层级与 “在访达中打开” 不变：不能拖动，按下与抬起照旧（见 03、08）
- `FolderPanelController.dragActions(for:in:containsScreenPoint:)` 只为 `.folder` 的层级给出 `FolderGridDragActions`，交给网格：
  - 屏幕上的点是否在当前层级的轮廓之内
  - 松开后保存新的顺序、删除这一项
  - `.finderFolder` 的层级为 nil：单元格没有转交拖动的对象，行为完全照旧

### 开始拖动

- 按下后移动超过 `FolderPanelMetrics.dragThreshold`（5 pt，与 Dock 判定拖动 tile 的阈值相同）即开始拖动
  - 没超过时照旧是按下与点击：压暗，在这一格里抬起才触发
- 一旦开始拖动，这次按下不再算点击：在哪里抬起都不打开、不启动、不进入
- 开始的一刻：
  - 按下的压暗恢复
  - 这一格的图标与名称隐藏，原处留出空位
    - 隐藏的是图标与名称两个子视图，不是单元格自己：拖动与抬起的事件仍发给按下的这个单元格
  - 网格还没建的单元格一次建齐：懒建是为访达里上千项的目录（见 08），文件夹的层级一般不多，让位只需移动已有的视图
  - 出现拖动图像：这一项的图标，与格里的图标同样大小（101 pt）、不透明、不压暗、不带名称
    - 按显示的大小与屏幕倍数取图，与格里的图标一样清晰：图标画进 101 pt 的图，再按 101 pt × 屏幕倍数的像素取出位图
    - 不用图标的 `layerContents(forContentsScale:)`：它按图标自己的 size 取图，放大到 101 pt 发糊（见 “平台事实”）
- 拖动图像跟随鼠标：图标中心与鼠标之差保持按下时的样子
  - 越过阈值的那一刻，图像相对原来的图标移过鼠标移过的距离，不跳到以鼠标为中心
- 拖动图像（`FolderGridDragImage`）在单独的无边框窗口里，出了面板窗口也看得见：
  - 窗口铺满图标中心所在的那块屏幕，图标是其中的一个图层；跟随鼠标时只移动图层，关掉独立图层的隐式动画
  - 图标中心移到另一块屏幕上时，窗口换到那块屏幕：frame 换成那块屏幕的 frame，图层按新的窗口原点重算位置，画面上图标的位置不变
  - 图标中心不在任何屏幕上（屏幕之间的空隙）时，窗口不动
  - 屏幕列表在开始拖动时取一次（`NSScreen.screens`）：拖动中屏幕参数变化会收起面板，拖动随之作废（见 “中断”）
  - 一个窗口只铺一块屏幕，不铺所有屏幕的并集：“显示器具有单独的空间” 打开（系统默认）时，一个窗口只显示在一块屏幕上
  - 层级是拖动图像的层级（`CGWindowLevelForKey(.draggingWindow)`，与系统拖放的拖动图像相同），高于面板
    - 在面板里抬起时，面板被排到同层级的最前（见 “平台事实”）；层级高于面板，落定途中面板怎么重排都盖不住它
  - 用 `orderFrontRegardless()` 显示；不接收鼠标事件、不成为 key，不激活 Flotilla（需求 6）
  - 面板窗口不在屏幕上时不显示：离屏的测试窗口里拖动，图像的窗口不上屏

### 拖动中

- 鼠标在当前层级的轮廓之内（面板主体与尾巴，与 `FolderPanelLevel.contains(screenPoint:)` 同一判定）：
  - 目标格 = 鼠标所在的格
  - 鼠标在网格的可见区域之外（标题区、两侧与底部的留白、尾巴）时，按离它最近的可见格算；露出一部分的行也算可见
  - 落在最后一项之后的空格，算作最后一格
  - 其余各项按 “拖动的项放到目标格” 之后的顺序让位，空位在目标格
- 鼠标在轮廓之外：拖动的项不占格，其余各项按原来的顺序补上空位，即删除之后的样子
- 进出轮廓、目标格变化时，各格从当前画面上的位置移到新的格，带动画
  - 对单元格图层的 `position` 加显式的 `CABasicAnimation`，从 `presentation()` 的当前值起始：动画途中目标又变，从当前画面接着移动，不跳、不闪
  - 原生 Dock 文件夹不能拖动排序，没有可对照的行为：时长与曲线沿用展开动画（`expandDuration` 0.23 s、`expandTimingControlPoints`）
  - 拖动的那一格看不见，直接放到目标格，不加动画
- 网格需要滚动时（超过 5 行）：
  - 鼠标在轮廓之内、在网格可见区域的上方或下方：随拖动自动滚动，每收到一次拖动对网格调用一次 `autoscroll(with:)`
  - 轮廓之外不滚动
  - 网格滚动之后（包括拖动期间用触控板或滚轮滚动），按鼠标最近一次的位置重新判定目标格

### 松开

- 在轮廓之内松开：
  - 拖动图像以同样的时长与曲线落进目标格的图标位置；落定后这一格显示出来，拖动图像消失
  - 目标格在面板所在的屏幕上：松开时拖动图像的窗口在别的屏幕上，先换到目标格所在的屏幕，再从画面上的当前位置开始落定
  - 落定途中网格滚动（例如松开时还有触控板或妙控鼠标的惯性滚动）：目标格不变，拖动图像的落点跟着目标格现在的屏幕位置
    - 图标图层放在容器图层里，落定动画在容器里进行；网格滚动时按目标格屏幕位置的变化平移容器，不加动画
    - 不重新开始动画、不改落定的时长：落定按松开时的时长收尾，收尾时图像正好在这一格上
  - 目标格与原来的位置不同：按新顺序保存（`FolderStore.move(itemID:to:at:)`，下标见后文）；相同：数据不变
  - 保存在落定之后：保存引起的重建（`DockFolderPresenter.folderStoreDidChange` → `FolderPanelController.reload()`）与落定后的画面一致，不跳
  - 落定期间（0.23 s）网格不响应新的按下（`hitTest(_:)` 返回 nil），免得在新旧顺序之间又开始一次拖动
  - 落定按时长收尾，不等 Core Animation 的完成回调，理由与 `afterAnimation` 相同：锁屏、显示器休眠时回调可能一直不来
  - 落定途中面板收起、或当前层级被重建：拖动图像立即消失，仍按松开时的结果保存
    - 收尾的任务自己持有保存的回调、拖动的项与目标格，不靠只被弱引用的网格
- 在轮廓之外松开：
  - 拖动图像立即消失，这一项从文件夹里删除（`FolderStore.remove(itemID:)`）
  - 子文件夹连同其中的内容一起删除，与设置窗口的 “删除” 相同，不弹确认
  - 删的只是文件夹里的这一项，不动磁盘上的 App 与文件
  - 删除后网格按剩下的项重建：格数变了，面板按新的格数重算尺寸，尾巴仍对准 tile（展示期间数据源变化的已有规则，见 03）；这一步不加动画
  - 面板保持展开：这次按下在面板里，不算点击面板以外

### 中断

- 拖动中面板开始收起（Esc、屏幕参数变化、当前文件夹被删等，见 03）：
  - `collapse()` 先让当前层级的网格作废拖动：拖动图像立即消失，不等收起动画结束
  - 网格恢复原来的样子，数据不变
- 拖动中当前层级被重建（数据源从别处变化，例如设置窗口、补标题、按书签跟随）：网格离开窗口时自己作废，同样数据不变
- 作废之后，这次按下剩下的拖动与抬起不触发任何点击、拖动或保存
- 单元格只把自己收到过按下、且没有变成拖动的那次抬起当作点击：按下之后网格被重建，新的单元格可能收到旧按下的抬起

### 点击穿透

- 鼠标在轮廓之外时点击穿透（`updateMousePassthrough`）只在鼠标移动时更新，拖动期间不变：按下的单元格才收得到拖动与抬起
- 拖动结束后：
  - 删除、保存：引起的 `reload()` 按鼠标当时的位置更新
  - 原地松开：鼠标在轮廓之内，面板照旧接收点击，与按下时相同
  - 作废：收起时点击全部穿透（见 03）；重建时由 `reload()` 更新

### 不变的

- 点击：按下、移动不超过 5 pt、在这一格里抬起，照旧打开、启动或进入
- 面板以外的点击、Esc、点击 tile 的规则不变（见 03）
- 顺序变了之后，Dock 上 tile 的预览按已有的同步规则更新，同步器不改（见 02）

### 交给 `FolderStore.move` 的下标

- `move(itemID:to:at:)` 的 `index` 按移动前的下标计算，同层向后移动时它自己减一
- 目标格 t（移动之后的下标）、原位置 d：传 `t > d ? t + 1 : t`，即 `FolderGridDragArrangement.moveIndex(from:to:)`
- 网格交出的是拖动的项与目标格；`FolderPanelController.dragActions(for:in:containsScreenPoint:)` 按建这一层时的各项找到原位置，再换算成这个下标

## 结构

- `FolderGridDragArrangement`：纯计算，与 `FolderGridLayout` 一样不依赖视图
  - 目标格：输入鼠标的位置与可见区域（网格坐标）、项数、列数
  - 各项所在的格：输入项数、拖动的项、目标格；鼠标在轮廓之外时目标格为 nil
  - 交给 `move` 的下标
- `FolderGridDragSession`：一次拖动的状态：拖动的项与它的单元格、图标中心与鼠标之差、鼠标最近一次的位置、当前的排列、拖动图像、是否正在落定
- `FolderGridDragImage`：拖动图像的窗口与图层；窗口跟到图标中心所在的屏幕，落定途中落点跟着目标格
- `FolderGridDragAnimation`：让位、补位与落定共用的位置动画
- `FolderGridDragActions`：面板交给网格的判定与动作
- `FolderGridView` 持有进行中的拖动，负责移动单元格；`FolderGridItemView` 只把开始拖动、拖动、松开转交给网格（`dragTarget`），没有转交对象时行为照旧

  - 交给 `move` 的下标：真的 `FolderStore`（临时文件），向后、向前与原地共 7 例，移动之后的顺序与拖动时网格显示的顺序相同

  - 删除回调删掉的只是这一项：子文件夹连同其中的内容，其它项不变，磁盘上的文件仍在

  - 落定途中网格滚动一行（网格比滚动视图高）：拖动图像的落点等于目标格滚动之后的屏幕位置；落定之后保存回调拿到的目标格不变
  - 落定按时长收尾，整套测试一起跑时回到主线程会晚到（见 “平台事实”）：测试按轮数等，不按时钟

## 验收

- `mise run swift:lint`、`swift test`、`mise run bundle` 全部通过
- 点击照旧：
  - 文件夹的层级里按下、几乎不动再抬起：App 启动、文件与网页打开、子文件夹与访达里的文件夹进入
  - 访达里的文件夹的层级里：按住一项拖出单元格再抬起不触发；“在访达中打开” 在哪里抬起都触发；都不出现拖动图像
- 开始拖动：
  - 按住一项移动超过 5 pt：这一格变空，图标跟着鼠标走，鼠标在图标上的位置与按下时相同，开始的一刻不跳
  - 拖动图像不压暗、不带名称，大小与格里的图标相同，与格里的图标一样清晰
- 让位：
  - 拖到另一格上，其余各项让位，空位跟着鼠标走
  - 在标题区、两侧与底部留白、尾巴上，空位在离鼠标最近的可见格
  - 拖到最后一项之后的空格，空位在最后一格
- 拖出面板：其余各项补位，最后一格空出；拖回面板又让出空位；拖动图像出了面板窗口仍跟着鼠标，排在面板之上
- 动画：让位、补位与落定都顺滑；快速来回移动时各格从当前画面接着移动，不跳、不闪
- 在面板里松开：
  - 图标落进空位，落定途中一直清晰地排在面板之上；落定后这一格显示出来，画面不跳
  - 设置窗口的文件夹树里顺序相同；退出重开 Flotilla 后顺序仍是新的
  - 在原来的格里松开：图标落回原处，顺序不变
- 在面板外松开：
  - 图标立即消失，这一项从文件夹里删除；面板按剩下的项重新排好，尺寸随之变化，尾巴仍对准 tile，面板保持展开
  - 拖出的是子文件夹时，其中的内容一起删除；磁盘上的 App 与文件都在
  - 之后鼠标移到轮廓之外，点击穿透到下面的窗口；点击面板以外照旧收起面板
- 超过 5 行的文件夹：
  - 拖到标题区或底部留白，网格随拖动滚动；拖动中用触控板滚动，空位按鼠标所在的格重新定位；拖到面板外不滚动
  - 在触控板上轻扫滚动、趁惯性滚动还没停时松开：图标跟着空位所在的格移动、落进这一格，落定后画面不跳
- 多显示器（需要两块屏幕）：
  - 把一项拖到另一块屏幕上：拖动图像跟过去、一直看得见，换屏幕的一刻不跳、不闪
  - 在另一块屏幕上松开：这一项从文件夹里删除
  - 从另一块屏幕拖回面板里松开：图标从画面上的当前位置落进空位
- 中断：
  - 拖动中按 Esc：面板收起，拖动图像立即消失，顺序不变
  - 拖动中在设置窗口改这个文件夹（例如加一项）：网格重建，拖动作废，松开不保存、不删除
- 根层级的前几项顺序变了：Dock 上 tile 的预览随之更新；Dock 重启时展开中的面板不受影响，位置与尾巴不变，之后照常拖动与点击
- 前台 App 全程保持前台，Dock 上没有 Flotilla 的活动图标（需求 6）

## 平台事实

以下都是 macOS 27 上的实测。

- 离屏窗口（从不排上屏幕，`defer` 为 true 或 false 都一样）：
  - 合成的鼠标事件经 `NSWindow.sendEvent(_:)` 发不到视图：按下、拖动、抬起都没有视图收到；测试把事件直接交给单元格
  - layer-backed 的子视图没有图层（`layer` 为 nil），显式设置 `wantsLayer = true` 才有
  - 有图层时改视图的 frame，图层的 `position` 立即同步（`anchorPoint` 为 (0, 0)）；`presentation()` 为 nil
  - 父窗口不在屏幕上时，`addChildWindow(_:ordered:)` 不把子窗口排上屏幕：子窗口 `isVisible` 为 false，窗口号为 −1，屏上窗口列表里没有它
- 从不排上屏幕的窗口（`defer` 为 true）对不存在的屏幕 frame 调 `setFrame(_:display:)`：
  - frame 原样接受，远在所有屏幕之外的也一样；`display` 为 true 或 false 都不上屏，窗口号仍为 −1
  - 托管图层的内容视图随窗口换成新的尺寸，它的图层（`anchorPoint` 为 (0, 0)）也一样
- 离屏窗口里独立图层上的显式动画：`presentation()` 为 nil；加上之后立即可以从图层上读到，运行循环转过动画的时长之后被移除
